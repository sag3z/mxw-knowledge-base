# Задача: гибридный поиск (смысл + точные слова) с фильтрами

Сейчас `/api/search` в `app/server.py` ищет только по эмбеддингам выжимок разговоров (`emb`, Qwen3-Embedding через `embed.embed()`). Точные названия, тикеры, ники (например «Ethereal», «o1.exchange», «1win») находятся плохо, а текст отдельных сообщений и расшифровки медиа не ищутся вообще.

Меняй только: новый `build_fts.py`, `app/server.py`, `app/index.html`. Не трогай `build_vault.py`, `layout.py`, `vault/`. Не читай `.llm_env`/`.openrouter_key`. НЕ открывай PNG инструментом Read (модель не принимает картинки — сессия падает).

## 1. `build_fts.py` — полнотекстовый индекс (SQLite FTS5, stdlib)
БД `data/kb.sqlite`. Таблицы: `messages(topic, id, ts, author, fwd_from, reply_to, text, media, media_text, is_bot)` — `media_text` это JSON-список `[{"kind":..., "text":...}]` (расшифровки голосовых/видео/описания фото); `convs(topic, conv, parent, msg_ids, verdict, category, tags, summary, scheme_summary, has_scheme, ...)` — `msg_ids` JSON-список id сообщений.
- Сначала проверь, есть ли в convs строки-родители, которые заменены сегментами (поле `parent` у сегментов): сообщение должно относиться к самому мелкому разговору (сегменту), а не к родителю. Если родительские строки в таблице не хранятся — просто сопоставь.
- Создай (пересоздавая) `fts_msg` (FTS5: `body`, UNINDEXED-колонки `topic, id, conv`) — текст сообщения + все media_text через пробел; пропусти is_bot=1 и пустые.
- Создай `fts_conv` (FTS5: `body`, UNINDEXED `topic, conv`) — summary + tags (через пробел) + scheme_summary.
- tokenizer: `unicode61 remove_diacritics 2` (русский + латиница). Печать: сколько строк в каждой.

## 2. `app/server.py` — новый поиск
`search(q, k, date_from, date_to, branch=None, category=None, schemes=False, drop=False)`:
- Смысловая часть: как сейчас (эмбеддинг запроса, косинус), берём топ-150 разговоров.
- Словесная часть: из запроса сделай FTS-запрос — слова длиной ≥2, каждое как префиксный термин в кавычках (`"ethereal"*`), объединённые через OR; экранируй кавычки. `fts_conv` по bm25 → топ-150 разговоров; `fts_msg` по bm25 → топ-300 сообщений, сгруппируй по (topic, conv): ранг разговора = лучший ранг его сообщений; сохрани до 3 лучших сообщений на разговор со сниппетом (`snippet(fts_msg, 0, '«', '»', '…', 14)`).
- Слияние: Reciprocal Rank Fusion, `score = Σ 1/(60 + rank)` по трём спискам (смысл, fts_conv, fts_msg). Если эмбеддинги недоступны (шлюз OpenCode API Manager выключен → `embed()` бросает исключение) — не падать, искать только по словам и вернуть флаг `"semantic": false`.
- Фильтры: даты (как сейчас, по start_ts), `branch` (короткое имя из SHORT, например `nft`), `category`, `schemes=1` → только has_scheme=1, `drop=1` → включать разговоры verdict='drop' (по умолчанию исключать — у них нет эмбеддингов, но в FTS они есть).
- Ответ: список `{id, score, date, topic, summary, category, has_scheme, hits:[{msg, author, snippet}]}`; сохрани прежние поля, чтобы дайджест (`digest()` использует `search`) не сломался. Если по результатам `drop`-разговор без summary — summary = первые 200 символов первого найденного сообщения.
- `/api/search` принимает новые параметры из query string: `branch, category, schemes, drop, from, to`.

## 3. `app/index.html` — панель «Поиск»
- Под полем ввода: компактный ряд фильтров — select «все ветки / <ветки из data.topics>», select «все категории / <из CAT>», чекбокс «только схемы», чекбокс «вкл. мусор». Изменение фильтра перезапускает поиск.
- Поиск запускается по Enter и по вводу с debounce 500 мс.
- В карточке результата под выжимкой показывай до 3 сниппетов сообщений (`hits`): «#id автор: …сниппет…», найденные слова (между « ») подсвети `<mark>`. Клик по сниппету открывает разговор (`openConv`) и прокручивает к этому сообщению с подсветкой (у сообщений в панели разговора проставь `id="m<msgid>"`, если ещё нет).
- Если ответ `semantic:false` — строка-предупреждение «смысловой поиск недоступен (не запущен OpenCode API Manager), ищу по словам».
- Подсветка найденных узлов на карте (уже сделана в задаче 003) должна продолжать работать.
