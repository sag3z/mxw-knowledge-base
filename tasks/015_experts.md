# Задача: «Кто в чём разбирается»

Меняй/создавай: новый `experts.py`, `app/server.py`, `app/index.html`. Не читай `.llm_env`/`.openrouter_key`, не читай `tasks/*.log`, НЕ открывай PNG.

## Данные (`data/kb.sqlite`)
- `messages(topic, id, ts, author, text, media_text, is_bot)`; `convs(topic, conv, verdict, category, tags JSON, key_msgs JSON, msg_ids JSON, has_scheme, scheme_types JSON, summary)`; `layout(topic, conv, x, y, k)` и `clusters(k, name, descr, n)` — смысловые кластеры (30 штук) для полезных разговоров.
- `key_msgs` — ключевые (содержательные) сообщения, отмеченные при разметке; это главный сигнал экспертизы.

## 1. `experts.py`
1. Для каждого автора (не бот): `n_msgs` (не-бот сообщения), `n_key` (сколько его сообщений в key_msgs полезных разговоров), `n_convs` (в скольких полезных разговорах у него есть ключевое сообщение), первая/последняя дата.
2. Экспертиза по темам трёх видов: кластер (`k` → name), категория (`category`), тип схемы (`scheme_types`, только для разговоров с has_scheme). Для пары (автор, тема): `n_key` в разговорах этой темы, `n_convs`, до 5 примеров разговоров (id `<short>-<conv>` — short как в SHORT из app/server.py) с наибольшим числом его ключевых сообщений. `score = n_key + 2 * n_convs`. Сохраняй пары со score ≥ 4.
3. Профили (LLM, DeepSeek через модуль `llm`): для топ-50 авторов по `n_key` — `llm.chat_json(llm.WRITER, SYS, user, max_tokens=3000, temperature=0.2, fallback=llm.ENTITY)`; материал: до 40 его ключевых сообщений (текст ≤400 симв + дата + тема-кластер), его топ-темы со счётчиками. Вернуть `{"profile": "2–3 предложения: в чём разбирается и чем полезен, конкретно (инструменты, сети, механики)", "skills": ["5–8 коротких навыков/тем"]}`. В SYS обязательно: НЕ писать имя/ник автора в тексте профиля (писать «Разбирается в…»), не упоминать никаких личных данных (город, возраст, работа вне крипты, реальные имена, контакты, кошельки), только экспертиза по материалу. Параллельно `ThreadPoolExecutor(3)` (лимит провайдера). Кэш `data/experts_profiles.json` по автору + хеш материала — повторный запуск не зовёт LLM.
4. Таблицы (пересоздавать): `experts(author PRIMARY KEY, n_msgs, n_key, n_convs, first_ts, last_ts, profile, skills JSON)` и `expert_topics(kind TEXT /*cluster|category|scheme*/, topic TEXT, author TEXT, score, n_key, n_convs, examples JSON)`.
5. Печать: топ-15 авторов (ник можно печатать — это локальная консоль), топ-3 эксперта для 10 крупнейших кластеров, usage.

## 2. Сервер
`GET /api/experts` → `{"people":[{author, n_msgs, n_key, n_convs, first_ts, last_ts, profile, skills, top:[{kind, topic, score}] (до 6)}], "topics":[{kind, topic, n_people, top:[{author, score, n_key, n_convs, examples}] (до 6)}]}`. Названия категорий — человекочитаемые (возьми словарь CAT из index.html или передай коды, а фронт переведёт по CAT). Типы схем → по-русски: multiaccount «Мультиаккаунты», antisybil «Антисибил», farms «Фермы», accounts «Аккаунты», bots_soft «Боты и софт», kyc_verification «KYC», proxy_antidetect «Прокси и антидетект», bans_risks «Баны и риски».

## 3. Фронт
- Кнопка «👥 Кто в чём» в `#top` (иконка + `.lbl`, как остальные; при открытой панели только иконка).
- Панель с двумя вкладками:
  - **По темам**: поиск-фильтр по названию темы; группы «Кластеры / Категории / Схемы»; у темы — топ людей: имя, полоска score (тонкая, одного цвета), «N ключевых сообщений в M разговорах», 1–3 примера-ссылки (клик → `openConv`).
  - **По людям**: список (сортировка по n_key), у каждого: имя, профиль, навыки чипами, топ-темы, период активности, примеры. Клик по имени — разворачивает.
- **Стример-мод**: везде в этой панели имя → псевдоним той же функцией, что в панели разговора (не дублируй — переиспользуй). Профили имён не содержат, их не трогать.
- Из панели разговора: клик по имени автора сообщения → открывает его карточку в «По людям» (в стример-моде тоже работает — по реальному автору, показывая псевдоним).
