# Задача: в ридере статей виден сырой frontmatter

Работай в `app/web/js/` (ридер статей — `openArticle`) и при необходимости `app/server.py` (`/api/article`). Не читай `.llm_env`/`.openrouter_key`, не читай `tasks/*.log`, НЕ открывай PNG. LLM не нужен.

Баг (ревьюер проверил через DevTools Protocol): при открытии ЛЮБОЙ статьи (`#/articles?article=Схемы/KYC и верификации.md`) в начале текста видна строка «категория: kyc_verification ветки: [ai, crypto, …] период: … источников: 48 модель: deepseek-v4.1-flash» — frontmatter не вырезается. Все .md в `vault/` сохранены с переводами строк Windows (`---\r\n…\r\n---\r\n`), а вырезание, видимо, ищет `\n---\n`. Исправь: вырезай frontmatter с учётом `\r\n` (лучше нормализовать `\r\n` → `\n` при чтении статьи) — и на сервере, и в автономном режиме архива (`api.js`, статьи из `window.MXW_DATA`), и везде, где парсятся поля frontmatter (плашка «проверено», `/api/articles`). Заодно проверь ридер в архиве после пересборки не нужно — достаточно кода.

ВАЖНО: основной сервер сайта на порту 8765 должен работать после твоей сессии. Если перезапускаешь его — только отвязанно: `Start-Process -WindowStyle Hidden -WorkingDirectory <папка проекта> -FilePath python -ArgumentList '-u','app/server.py','8765'`; для своих тестов поднимай отдельный экземпляр на другом порту (например 8799) и останавливай только его. В прошлый раз сервер 8765 остался выключенным после проверки.

Проверка: через DevTools Protocol открыть 3 статьи (KYC и верификации, Прокси и антидетект, любую из `Проекты и инструменты/`) — в тексте drawer нет подстрок «категория:», «модель:», «ветки:»; плашка «✓ проверено …» у «Прокси и антидетект» на месте. `node --check`. В конце — `curl http://127.0.0.1:8765/` → 200.
