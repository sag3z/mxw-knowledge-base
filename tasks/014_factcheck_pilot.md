# Задача: проверка фактов в статьях второй моделью — ПИЛОТ на 10 статьях

Статьи в `vault/` (папки категорий, `Схемы/` с подпапками, `Проекты и инструменты/`) написал DeepSeek (`deepseek-v4.1-flash`) по разговорам из `data/kb.sqlite`. Ссылки на источники в тексте: `[[<short>-<conv>]]` (например `[[crypto-c0008]]`, `[[nft-c0083-01]]`), short → slug темы: nft=nft_движуха, ai=ai_вайбкод_билдинг_хакатоны, life=жизнь_флуд_кайф, crypto=крипта_работа_проекты, perps=перпы_фандинг_dex_ы, predict=предикшены_и_ставки, soft=софты, shitki=щитки_мемы_деген_плеи, important=важное_саммари_и_коллы. Таблицы: `convs(topic, conv, msg_ids JSON, key_msgs JSON, summary, ...)`, `messages(topic, id, ts, author, text, media_text JSON [{kind,text}], is_bot)`.

Цель — проверить ВЕРНОСТЬ ИСТОЧНИКАМ (не истинность в мире): каждое фактическое утверждение статьи должно подтверждаться сообщениями разговоров, на которые оно ссылается.

Создай `factcheck.py` (LLM через модуль проекта `llm`). Не читай `.llm_env`/`.openrouter_key`, не читай `tasks/*.log`, НЕ открывай PNG. Статьи в этом пилоте НЕ изменять.

## Алгоритм
1. Статья → разделы по заголовкам `##` (frontmatter выкинуть). Для каждого раздела: множество ссылок `[[…]]` в нём, которые резолвятся в разговоры.
2. Материал раздела: сообщения цитируемых разговоров — сначала ключевые (key_msgs), затем остальные по порядку; каждое строкой `#<id> <YYYY-MM-DD HH:MM> <автор>: <текст> ⟪<kind>: <расшифровка до 800 симв>⟫`; пропускать is_bot и пустые; ограничение ~60k символов на раздел (если больше — сначала ключевые и сообщения, содержащие слова из раздела, потом остальные). Разделы без ссылок — тоже проверять (утверждения получат «no_source»), материал пустой.
3. Судья — `glm-5.3` (константа `JUDGE`; НЕ та модель, что писала): `llm.chat_json(JUDGE, SYS, user, max_tokens=12000, temperature=0, fallback="deepseek-v4-pro")`. SYS (по-русски): разбей раздел на атомарные фактические утверждения (цифры, даты, названия, кто что сказал/сделал, условия, результаты; оценочные обобщения тоже — как утверждения); для каждого — вердикт:
   - `supported` — прямо подтверждается; укажи `evidence` (id сообщений) и короткую цитату `quote` (≤200 симв, из материала дословно);
   - `partial` — суть верна, но неточность (цифра, дата, автор, преувеличение/обобщение из единичного случая) — опиши в `problem`;
   - `unsupported` — в материале этого нет;
   - `contradicted` — материал говорит обратное (цитата обязательна);
   - `no_source` — у утверждения нет ссылки в разделе;
   плюс `hedge_ok`: если в источнике это только чьё-то мнение/слух, а в статье подано как факт без «по словам» — false. Для partial/unsupported/contradicted — `fix`: как переписать предложение по материалу (или «удалить»).
   Формат: `{"claims":[{"text":"…","verdict":"…","evidence":[…],"quote":"…","problem":"…","hedge_ok":true,"fix":"…"}]}`.
4. Валидация: evidence — только id из материала (иначе убрать; supported без валидного evidence → понизить до `unsupported?` с пометкой `judge_no_evidence`); quote проверь на дословное вхождение в материал (нормализуя пробелы/регистр) — не вошла → флаг `bad_quote`.
5. **Второе мнение** для `unsupported` и `contradicted`: тот же раздел + только эти утверждения → модель `qwen3.8-max` (константа `SECOND`; если она недоступна/ошибка — `deepseek-v4-pro`), вопрос: «подтверждается ли утверждение материалом? верни supported/partial/unsupported/contradicted + evidence + quote». Итоговый вердикт: если второе мнение `supported` с валидной цитатой — `disputed` (спорное), иначе — вердикт судьи с пометкой `confirmed_by_second`.
6. Параллельность: разделы через `ThreadPoolExecutor(3)` (у провайдера лимит 3 параллельных запроса — не больше).
7. Результат: `data/factcheck/<safe-имя статьи>.json` (все утверждения по разделам) + общий отчёт `data/factcheck/report.md`: таблица по статьям (утверждений, % supported, partial, unsupported, contradicted, no_source, disputed, hedge-проблем, время, вызовов LLM) и далее по каждой статье список проблемных утверждений: вердикт, текст, проблема, цитата/evidence `[[conv]] #id`, предлагаемая правка. Кэш/resume: готовые статьи не перепроверять (флаг `--force`).

## Выборка пилота (`python factcheck.py --pilot`)
10 статей, детерминированно (random.seed(7)): 2 из `NFT/`, по 1 из `AI, вайбкодинг и разработка/`, `Трейдинг, перпы, арбитраж, мемкоины/`, `Безопасность и скамы/`, `Дропы, тестнеты и фарм активностей/`, 1 схема верхнего уровня из `Схемы/` (не хаб), 1 подстатья из `Схемы/Боты и софт (формы, минт, регистрация)/`, 2 карточки из `Проекты и инструменты/` с наибольшим числом упоминаний (frontmatter `упоминаний`). Также `python factcheck.py <путь к .md> [...]` — проверить конкретные.

## Запуск и отчёт
- Запусти `python factcheck.py --pilot` (LLM вызывать можно — это и есть задача). Если долго — запускай отвязанно в фоне и дождись (до 40 минут), периодически проверяя наличие json-файлов.
- В отчёте сессии: таблица по 10 статьям, суммарно вызовов и токенов (`llm.usage`), среднее время на статью, 10 самых показательных найденных проблем (текст утверждения, вердикт, цитата).
