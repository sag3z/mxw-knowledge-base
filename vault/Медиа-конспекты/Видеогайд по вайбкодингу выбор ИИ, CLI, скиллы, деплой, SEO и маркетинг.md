# Видеогайд по вайбкодингу: выбор ИИ, CLI, скиллы, деплой, SEO и маркетинг

- Источник: ветка жизнь_флуд_кайф, сообщение #10078, video_files
- Категория: ai_dev
- Теги: вайбкодинг, claude, codex, cli, skills, mcp, vercel, github-actions, vps, fail2ban, seo, umami, web3

## Кратко
Видеогайд автора (Максим, по тексту) для новичков в вайбкодинге: как выбрать ИИ, поставить CLI, настроить скиллы и MCP, сделать сайт, поднять его на сервер с CI/CD и настроить SEO и маркетинг. Главный вывод автора: почти всё (настройка, выбор стека, сервер, домен, безопасность, SEO) нужно спрашивать у самой ИИ-модели, а не у людей в чатах. Видео записано для Web3-аудитории, часть советов привязана к конкретным сервисам и ценам на момент записи.

## Главное
- Выбор ИИ: по мнению автора, всерьёз рассматривать стоит только Claude и Codex. Claude — подписка от $100 (ниже, по его словам, для работы бесполезно, $20 — только для теста). Codex можно вести на нескольких аккаунтах.
- Дешевле: автор говорит, что подписки продают через перепродажу (GGSell, Plati Market, FunPay) и что там часто аккаунты из других регионов. Такие доступы он называет «абузами», которые быстро теряют актуальность, и сам их не показывает. Свой основной аккаунт автор оплачивает картой Soul Card.
- Установка на Windows: через Windows Terminal (команда `wt` из папки); для Claude — отдельная команда установки из документации, Node.js ставится сам. При первом запуске — ссылка на подписку и API-ключ.
- Режим размышления: автор ставит effort max на каждую сессию (по его словам, у Claude по умолчанию x-high). Чтобы не подтверждать каждое действие, он просит ИИ убрать запросы approve и включить автоматическое принятие правок.
- Рабочая схема: открываешь CLI в папке проекта, ИИ сам создаёт память и сессии; ставит скиллы superpowers, playwright MCP, frontend design, context7, vercel best practices. По словам автора, ставить их достаточно попросить самой ИИ.
- Память и правила, которые автор записывает в глобальную память ИИ: пушить и коммитить изменения на GitHub автоматически; описания и зависимости писать на английском; тире в описаниях — длинное, а не дефис; не предлагать первый вариант решения, сначала изучить проект.
- Идея: автор рекомендует начинать с выбора проекта под хакатон или под существующий проект, а не с нуля (по его словам, за день можно сделать до трёх небольших проектов при фуллтайме).
- Дизайн: просить ИИ сделать отдельный HTML-файл с 30–50 вариантами оформления и выбрать лучший; для эффектов — React Bits и Variance (код копировать как TypeScript + Tailwind, либо отправлять скриншот). Говорить ИИ, что нужен не «ИИшный» дизайн.
- Стек: сразу указать ИИ максимальный стек (Next.js и т.п.), а не чистый HTML/CSS.
- Деплой: GitHub → автодеплой через GitHub Actions (CI/CD). Лёгкий сайт — бесплатно на GitHub Pages или Vercel.
- Серверы по версии автора: ForVPS — самый простой и надёжный на старте; Netcup — хорош; Hetzner — дешёвый, но «сам ебёшься»; OVHcloud — полегче; Cloudzy — конфиденциальный; Azure — автор там хостит свой проект, но сервер однажды взломали.
- Взлом: по словам автора, сервер на Azure взломали на следующий день после того, как ИИ сам настроил его с нуля (автор передал данные доступа); в тексте упомянута утечка и использование сервера для DDoS. Автор сам связывает это с тем, что безопасность не задавалась отдельной задачей.
- Безопасность (минимум по мнению автора): fail2ban и вход по SSH-ключу вместо пароля; затем попросить ИИ пройтись по проекту и найти баги и улучшения. Автор отмечает, что сервер сразу начинают атаковать, как только он появляется в сети.
- Домены: Spaceship или Namecheap; автор покупает на Spaceship картой Soul Card; .xyz — около $1,86 в год, .com — около $8. DNS — Cloudflare. Если нужна аудитория из России и СНГ, оранжевое облако Cloudflare, по совету автора, отключают; если она не нужна — оставляют включённым, и оно даёт защиту от DDoS.
- Настройка домена и сервера, по словам автора, занимает около 30 минут и ещё примерно 2 часа ожидания распространения DNS.
- SEO: URL-роутинг (языки, вкладки), sitemap, регистрация в Google Search Console, затем импорт в Bing и Yandex Webmaster. Индексация занимает 2–3 дня, поэтому SEO лучше включать сразу.
- Аналитика: Umami — по словам автора, не собирает куки и подходит для крипто-сайта лучше остальных. Visits и views считаются по-разному; события (например, смена темы) можно настроить через ИИ.
- Маркетинг: по мнению автора, соотношение 70–85% разработка и 15–30% маркетинг. Посты в X и TG, нативно и с пользой; тирлисты в X по его опыту собирают 5–6 тыс. просмотров за 20 часов; платную рекламу автор не использовал.
- Конкуренция (по мнению автора): почти нет конкурентов в фандинг-сканерах и в сервисах, где есть польза для людей. Указаны ниши: Abstract, Base, Ink, LitVM, MegaETH, Doma, Arc (коллекции на Arc, по его словам, низкого качества). Идея — свой прокси-сервис с дешёвыми дата-центр тарифами, лучше ProxyShare и Webshare по интерфейсу.
- Хакатоны и задания: автор упоминает SuperTeam Frontier и Opinion (по его словам, за вайбкод-приложения платили $1000–2500). Учиться лучше на контрибьюте в чужие проекты.
- Собственный проект автора: maxy.tools — тирлист Web3-проектов с разделами Tools, Funding Farm, AI & Building, Extra (в том числе Role Farming — Discord-серверы активных проектов). По словам автора, это его личный сервис, который он делал за несколько дней с ИИ.
- Ограничения, которые автор признаёт: ИИ не знает свежих локальных трендов; тексты пишет хорошо, идеи для кликбейта и постов — хуже; Grok может проверять X.
- Сроки и ошибки: первый вариант ИИ часто криво; модели любят «зацепиться» за одну идею и тянуть её даже при ошибке, поэтому нужен контроль.
- Замечание автора о Vercel: по его словам, взломали часть проектов, где лежали статичные одностраничники без данных.
- Отдельное мнение автора: вайбкодинг — лучший путь для новичков, учить Python/JS «три года» он считает неэффективным; это спорная позиция, которую он сам оценивает как непопулярную.
