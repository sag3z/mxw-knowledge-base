# Задача: factcheck.py v2 — ложные срабатывания, неверные ссылки, скорость

Меняй только `factcheck.py`. Не читай `.llm_env`/`.openrouter_key`, не читай `tasks/*.log`, НЕ открывай PNG. Статьи в `vault/` не менять.

Пилот (5 статей готово, `data/factcheck/*.json`) показал три проблемы:

1. **Неверная ссылка ≠ выдумка.** Статья «Telegram-подарки…» ссылается на `[[life-c0254]]`, судья пометил 12 утверждений `unsupported` — но всё это реально есть в соседнем разговоре `life-c0255` (обсуждение разрезано на два по паузе 45 мин; например, «getgifts» — сообщение #16057 в c0255). Нужно: для каждого утверждения с итоговым `unsupported` (и `contradicted`) искать настоящий источник:
   - кандидаты: соседние разговоры той же темы (±3 по номеру conv / по времени ±12 ч) + FTS по `fts_msg` (таблица из build_fts.py: `fts_msg(body, topic UNINDEXED, id UNINDEXED, conv UNINDEXED)`; запрос из значимых слов утверждения — существительные/названия/числа, OR, префиксы), топ-5 разговоров;
   - собрать материал из этих кандидатов и одним вызовом спросить судью, подтверждается ли утверждение там; если да — вердикт `wrong_citation` с полем `correct_source: "<short>-<conv>"`, evidence и quote (с валидацией дословности, как сейчас);
   - в отчёте `wrong_citation` — отдельной колонкой и группой «исправить ссылку: [[старая]] → [[новая]]».
2. **Обрезка расшифровок даёт ложные «нет в материале».** `MEDIA_LIMIT = 800` — утверждения про кадры видео/скринов не находятся, потому что мы сами обрезали текст. Сделай: расшифровки до 4000 символов; если материал раздела превышает лимит — сначала ключевые сообщения и сообщения/расшифровки, содержащие слова раздела, полностью, остальные — обрезанными. И если судья в `problem` пишет, что текст обрывается/обрезан — повторить это утверждение с полной расшифровкой соответствующего сообщения.
3. **Скорость: 20–70 минут на статью** (GLM медленный, ответы упираются в `max_tokens=12000` → truncated → повторы). Сделай:
   - судья по умолчанию `qwen3.8-max` (быстрый, не та модель, что писала статьи), второе мнение — `glm-5.3`; константы `JUDGE`/`SECOND` + флаги `--judge`/`--second`;
   - большие разделы делить: не более ~25 утверждений на вызов — проси модель сначала только список утверждений (короткий вызов), потом проверка пачками по 25 с тем же материалом; компактный JSON (без повторения текста утверждения в ответе — по номеру);
   - статьи параллельно: `ThreadPoolExecutor` общий на все вызовы, максимум 3 одновременных запроса к провайдеру (семафор в одном месте);
   - в json и отчёте — время и число вызовов на статью.
4. Старые json пилота пересчитай: `python factcheck.py --pilot --force` (10 статей). Цель — ≤ 5 минут на статью в среднем; если не выходит — напиши, что тормозит (по `data/llm_calls.log`: время между вызовами, out-токены).
