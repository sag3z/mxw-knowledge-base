# Задача: смысловой поиск в архиве без ключа — локальная модель прямо в браузере

Прочитай `tasks/DESIGN.md` (раздел «Код»). Не читай `.llm_env`/`.openrouter_key`, не читай `tasks/*.log`, НЕ открывай PNG. Меняй: `app/web/js/api.js` (автономный режим), при необходимости новый `app/web/js/embed_web.js`, `export_static.py`. Серверный режим не ломать.

## Сейчас
Архив (`export_static.py` → `dist/MXW-база-<дата>/`, открывается двойным кликом через `file://`) для смыслового поиска берёт старые векторы Qwen3-Embedding-8B (2048-d, `emb.js` 4.4 МБ) и эмбеддит запрос через API получателя (нужен ключ OpenRouter). Локальный сервер уже перешёл на `multilingual-e5-small` (384-d, ONNX quantized, `embed_local.py`, файлы модели в `models/e5-small/`: `tokenizer.json`, `model_quantized.onnx`; mean pooling по attention_mask + L2; префиксы `"query: "` / `"passage: "`; таблицы `emb_local`, `emb_art`).

## Нужно
1. Архив использует **те же e5-small векторы**: `emb_local` (разговоры) и `emb_art` (куски статей) квантованные в int8 (масштаб на вектор), base64 в `app/data/emb.js`. Старые 2048-d — убрать.
2. **Эмбеддинг запроса в браузере без сети и без ключа**: onnxruntime-web (wasm, однопоточный, без SharedArrayBuffer) + токенайзер из `tokenizer.json` (можно токенайзер из transformers.js или свою реализацию WordPiece/Unigram — у e5-small XLM-R SentencePiece/Unigram, проверь по tokenizer.json; проще всего взять `@huggingface/transformers` ESM/UMD-сборку и использовать только `AutoTokenizer` + `env` с локальными файлами). Ограничение `file://`: браузер не даёт `fetch` локальных файлов → модель (`model_quantized.onnx`, ~110–120 МБ), `tokenizer.json` и `ort-wasm*.wasm` упаковать в JS-файлы (`app/model/*.js`, base64 частями по ≤ 20 МБ, подключаются `<script>` динамически при первом поиске, собираются в `Uint8Array`), сессия создаётся из буфера (`ort.InferenceSession.create(uint8array)`, `ort.env.wasm.wasmBinary = arrayBuffer`, `numThreads = 1`, `proxy = false`). Библиотеки — локально в архиве (без CDN).
3. Загрузка модели — лениво при первом вопросе/поиске с индикатором «Загружаю модель поиска… (один раз, ~10 с)»; после — запрос < 0.5 с. Если что-то не удалось — поиск по словам, как сейчас, с понятным сообщением.
4. **Совпадение векторов с сервером**: проверь в Node (onnxruntime-node не нужен — используй тот же onnxruntime-web в Node или сравни через headless Edge) на 5 строках, что косинус между вектором из браузерной реализации и `embed_local.embed_query` (Python) ≥ 0.99.
5. Чат в архиве: источники ищутся этим локальным смысловым поиском + словами; ключ нужен только для генерации ответа ИИ (без ключа — показываются источники и подсказка про ⚙ Настройки). Настройку «модель эмбеддингов» в окне настроек убрать (больше не нужна).
6. Пересобери архив: `python export_static.py` (полный). Обнови `ПРОЧТИ.txt`: смысловой поиск работает без ключа; ключ OpenRouter нужен только для ответов ИИ в чате.
