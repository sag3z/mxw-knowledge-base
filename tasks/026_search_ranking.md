# Задача: ранжирование поиска — смысл главный, слова бонусом; расширение через LLM не дольше 8 с

Меняй только `app/server.py`. Не читай `.llm_env`/`.openrouter_key`, не читай `tasks/*.log`, НЕ открывай PNG. ВАЖНО для проверок: кириллицу в запросах кодируй через Python `urllib.parse.urlencode` — curl из Git Bash портит кириллицу в аргументах (ревьюер на этом попался).

## Наблюдения ревьюера (замеры через urllib)
- Чистый смысловой поиск по `emb_local` (e5-small) хороший: на «Какие антидетекты советовали для мультиаккаунтов?» топ-5 по косинусу — про мультиаккаунты, гайд ADSpower, Dolphin{agent}, антидетект-браузеры.
- После RRF со словесными списками (`fts_conv`, `fts_msg`) выдача портится: в топ-6 «The Unstables профиль на скрине», «рефералка брокера», «Минт onchainharvest» — их тянет FTS по префиксу `"советовали"*` и т.п.
- `expand=1` (LLM-ключевые слова) улучшает, но занимает 23–94 с (провайдер медленный) — для чата неприемлемо.

## Сделать
1. **Новое ранжирование** в `hybrid_search`:
   - Кандидаты: топ-120 по смыслу ∪ топ-60 `fts_conv` ∪ топ-60 разговоров из `fts_msg`.
   - Для каждого кандидата `sim` = косинус запроса с его вектором из `emb_local` (у drop-разговоров вектора нет — `sim` = минимальный sim среди кандидатов − 0.01).
   - Итоговый скор: `score = sim_norm + 0.15 * kw_conv + 0.08 * kw_msg + 0.05 * keep`, где `sim_norm` — sim, линейно нормированный по кандидатам в [0, 1]; `kw_conv` ∈ [0, 1] — доля РАЗНЫХ значимых термов запроса/keywords, найденных в выжимке+тегах разговора (fts_conv body); `kw_msg` — 1, если есть совпадения в сообщениях, иначе 0; `keep` — 1 для verdict='keep'. Значимые термы — после стоп-слов, плюс отфильтруй «общие» глаголы/слова по документной частоте: терм, встречающийся более чем в 4% разговоров `fts_conv`, не даёт бонус (считай df один раз и кэшируй).
   - Сниппеты `hits` — как сейчас из fts_msg.
2. **Расширение через LLM — с жёстким таймаутом**: вызов в отдельном потоке, ждать не больше 8 с; не успел — продолжать без keywords (результат LLM, если придёт позже, положить в кэш для следующего раза). Кэш расширений по нормализованному тексту вопроса (LRU 500). Тот же таймаут — для переформулировки в чате (если она объединена с расширением — это один вызов).
3. Для чата (`/api/chat`): источники берутся из нового ранжирования; если `expand` не успел — используется только смысл+слова вопроса.
