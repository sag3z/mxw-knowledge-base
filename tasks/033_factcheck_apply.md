# Задача: применить результаты проверки фактов к статьям хранилища

Не читай `.llm_env`/`.openrouter_key`, не читай `tasks/*.log`, НЕ открывай PNG. Создай `factcheck_apply.py`. Модели: только Qwen (`llm.QWEN`, fallback `llm.QWEN_ALT` — см. llm.py), официальный DeepSeek (`ds:`) НЕ использовать. Параллельно идёт долгий прогон `factcheck.py --all` (он пишет `data/factcheck/*.json`) — его НЕ останавливать и НЕ трогать `factcheck.py`.

## Данные
`data/factcheck/<имя>.json` — результат проверки статьи: `article` (путь .md), разделы `sections[]` с `heading`, `claims[]` (`text`, `verdict`/`final`: supported | partial | unsupported | contradicted | wrong_citation | disputed | no_source; `evidence` (id сообщений), `quote`, `problem`, `fix`, для wrong_citation — `correct_source` вида `<short>-<conv>`, исходная ссылка в тексте раздела — `[[<short>-<conv>]]`).

## Что делать со статьёй
1. **wrong_citation** → в предложении статьи, где стоит утверждение, заменить неверную ссылку `[[старая]]` на `[[correct_source]]` (если в предложении несколько ссылок — заменить ту, что указана как неверная; если не удаётся однозначно найти — добавить правильную ссылку рядом, старую оставить). Проверить, что файл `vault/Источники/<short>/<correct_source>.md` существует.
2. **contradicted** (и подтверждённое вторым мнением) → переписать предложение по `fix`/цитате источника — одним вызовом Qwen на раздел: дать модели текст раздела, список проблемных утверждений с `fix` и цитатами; модель возвращает исправленный раздел целиком; проверка: все `[[...]]` ссылки исходного раздела сохранены (кроме заменённых по п.1), длина не меньше 70% исходной, markdown-структура (заголовок раздела) на месте — иначе правку раздела отбросить и просто пометить (п.3).
3. **unsupported** → не удалять, а пометить: после предложения вставить `⚠️` со сноской Obsidian: `^[не подтверждено источником при проверке <дата>]` (формат `^[...]` — inline-сноска Obsidian). **partial** — только если в `problem` речь о неверной цифре/дате/авторе: исправить по п.2; иначе не трогать. `disputed`, `no_source`, `supported` — не трогать.
4. В frontmatter статьи добавить/обновить: `проверено: <дата>`, `утверждений_проверено: N`, `подтверждено: X%`, `исправлено: K`.
5. Для поиска утверждения в тексте: текст утверждения — перефраз, поэтому ищи предложение раздела с максимальным совпадением (общие значимые слова/числа/названия, ≥ 0.5 по доле слов утверждения); не нашёл — пропусти и запиши в лог.

## Режимы
- `python factcheck_apply.py --dry [пути или --all]` — ничего не пишет, для каждой статьи печатает diff (unified, укороченный) и итог: заменено ссылок, переписано разделов, помечено утверждений, не найдено.
- `python factcheck_apply.py [--all | пути]` — применяет; перед записью копия исходной статьи в `backup/vault_before_apply/<путь>`; повторный запуск идемпотентен (уже помеченное/исправленное не трогает — смотри frontmatter `проверено` и наличие ⚠️-сноски).
- Применяет только для статей, у которых есть json проверки.

## Проверка
- `--dry` на 10 статьях пилота (`python factcheck.py --pilot` печатает их список, или возьми самые свежие json) → покажи в отчёте 3 полных примера изменений (до/после фрагмента) для каждого типа: замена ссылки, переписанное предложение, пометка ⚠️.
- После dry — примени ТОЛЬКО к этим 10 статьям, затем `python build_vault.py index` и `python check_vault.py vault` — битых ссылок 0. Остальные статьи не трогать (прогон ещё идёт).
