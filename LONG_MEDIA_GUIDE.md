# Инструкция: конспекты длинных медиа-документов

В `data/long_media/<ветка>/<msg>__<тип>.txt` лежат длинные расшифровки и файлы из чата комьюнити MXW: видео и голосовые админа, гайды, текстовые файлы, списки содержимого архивов. Для каждого сделай конспект для базы знаний.

Выход: `data/long_media_notes/<ветка>/<msg>__<тип>.md` (тот же путь, расширение .md):

```markdown
# <короткий заголовок по сути>

- Источник: ветка <ветка>, сообщение #<msg>, <тип>
- Категория: <одна из категорий SORTING_GUIDE.md>
- Теги: tag1, tag2, ...

## Кратко
2–4 предложения: о чём это и главный вывод.

## Главное
Пункты с конкретикой: инструменты, шаги, цифры, советы, предупреждения, мнения автора (с пометкой «по мнению автора»). Схемы (мультиаккаунты, фермы, KYC, софт и т.п.) фиксируй так же конкретно, как всё остальное — это нужно владельцу базы.
```

Правила: только то, что есть в тексте, ничего не додумывай; длина конспекта — по содержанию (от 5 до 40 пунктов); пустую болтовню и шутки пропускай; рефералки, ключи, пароли, адреса кошельков не переписывай. Если документ — список файлов архива, опиши, что это за софт судя по именам файлов, одним абзацем.
