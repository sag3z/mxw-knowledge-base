# Задача: чат с базой (диалог с уточняющими вопросами, потоковый ответ)

Сейчас есть разовый «Дайджест по запросу» (`POST /api/digest` → `digest()` в `app/server.py`: hybrid `search()` → материал из выжимок и ключевых сообщений → `llm.chat(llm.WRITER, DIGEST_SYS, …)` → ответ со ссылками `[[id]]`). Нужен полноценный чат.

Меняй: `llm.py` (только добавить функцию), `app/server.py`, `app/index.html`, новый `build_fts.py` можно дополнить. Не читай `.llm_env`/`.openrouter_key`, не печатай ключи, не читай `tasks/*.log`, НЕ открывай PNG.

## 1. `llm.py`: потоковая генерация
Добавь `chat_stream(model, system, messages, max_tokens=4000, temperature=0.3)` — генератор кусков текста, на основе существующего `_stream` (тот же SSE-разбор с буфером многострочных событий; `messages` — список `{role, content}` после system). Логируй usage в `data/llm_calls.log` как `chat()`. Существующие функции не менять.

## 2. Статьи базы в поиске
В `build_fts.py` добавь таблицу `fts_art(body, path UNINDEXED, title UNINDEXED)`: все .md в `vault/` кроме `vault/Источники/`, разбитые на куски по заголовкам `##` (≤2500 символов, frontmatter выкинуть). Запусти `python build_fts.py`.

## 3. Сервер: `POST /api/chat`
Тело: `{"messages":[{"role":"user|assistant","content":"…"}], "from":null, "to":null, "pin":"<conv id или путь статьи или null>", "anon":false}`.
1. **Переформулировка**: если сообщений больше одного — коротким вызовом `llm.chat(llm.WRITER, …, max_tokens=200, temperature=0)` преврати последний вопрос с учётом истории в самостоятельный поисковый запрос (например «а кто это пробовал?» → «кто пробовал Ethereal клейм»). Иначе — сам вопрос.
2. **Поиск**: `search(query, k=18, …)` (hybrid, как digest) + 3 лучших куска статей из `fts_art` (bm25). Если `pin` — разговор: он идёт первым в материал целиком (не-noise сообщения, до 60); если `pin` — статья: её текст первым (до 12000 символов).
3. **Материал**: как в `digest()` (переиспользуй/вынеси общую функцию сборки блоков). Статьи — блоком `[[<название статьи>]] <кусок>`. Если `anon` — в материале заменяй имена авторов на псевдонимы «Участник XXX» той же функцией хеша, что фронт (FNV-1a → 3 hex; повтори на Python так, чтобы совпадало с JS — проверь на 3 никах), чтобы модель не называла ники.
4. **Ответ**: `llm.chat_stream(llm.WRITER, CHAT_SYS, history)`; где history = последние 8 сообщений диалога, а к последнему user-сообщению приклеен материал. CHAT_SYS — на основе DIGEST_SYS + «это диалог; на уточняющие вопросы отвечай с учётом предыдущих ответов; если в материале ничего нет — так и скажи и предложи, как переформулировать».
5. Отдача: `text/event-stream`: сначала событие `meta` с `{"query": …, "sources":[{id, date, topic, summary}], "articles":[{title, path}]}`, затем события `delta` с кусками текста, в конце `done`. Пиши в сокет с flush; при обрыве клиентом — тихо прекратить генерацию. Ошибка LLM → событие `error`.
6. Ссылки `[[…]]`, которых нет среди источников/статей материала, фронт показывает как обычный текст (сервер при потоковой отдаче их не вычищает — пусть фронт проверяет по meta).
`/api/digest` оставить как есть.

## 4. Фронт
- Кнопку «🎧 Дайджест по запросу» заменить на «💬 Чат» (иконка + `.lbl`, как другие кнопки). Панель чата: лента сообщений (вопросы справа, ответы слева, markdown через marked + `linkify` для `[[…]]`), поле ввода снизу (Enter — отправить, Shift+Enter — перенос), кнопка «новый чат», выбор периода как был в дайджесте (всё / 7 / 30 / 90 дней).
- Ответ появляется по мере генерации (читай поток через `fetch` + `ReadableStream`, разбирай SSE). Под ответом — свёрнутый список источников (`<details>`), клик → `openConv`.
- История: текущий диалог и список прошлых (до 20) в `localStorage`; «новый чат» начинает пустой, прошлые открываются из списка.
- Контекст: в панели разговора и в окне статьи кнопка «💬 спросить про это» — открывает чат с `pin` (показать плашку «контекст: …» с крестиком).
- Стример-мод: передавать `anon: true`, в ленте ников нет (ответы модели и так будут с псевдонимами).
- Возврат кнопкой «←» из открытого разговора обратно в чат должен сохранять ленту (посмотри, как устроен `panel()`/history — чат не должен пропадать).
